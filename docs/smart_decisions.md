# Smart Decisions — implementation and QA guide

**Scope:** MoneyLab's November 2026 decision-language flow. It does not add a
general AI chatbot, storage backend, or new account permissions.

## First-run experience

1. Open **Home**. The "Describe a money decision" box appears before the
   suggested decision buttons.
2. Enter one straightforward decision:
   - "I want to move out. New rent would be $1,500 per month; I take
      home $3,500 monthly, and I have $8,000 saved."
   - "I want a gym membership that costs $45 per month."
   - "I want to buy a $3,000 vacation."
3. Click **Understand my decision**. A temporary review panel identifies
   the decision category, suggested amounts, missing essentials, and
   anything the parser could not confidently interpret.
4. Edit the figures if necessary. For recurring costs, explicitly choose
   a frequency if the description left it out.
5. Click **Open my decision with these values**. Moving routes to the
   existing **Moving Out Decision Lab** with *your entered assumptions*;
   purchases and recurring costs route to **Decisions**, including a
   temporary comparison for users with no saved profile.
6. Complete any remaining unknown inputs, run the existing deterministic
   financial comparison, edit assumptions, and rerun without restarting.
7. Your existing financial blocks in **My Money** are **never silently
   modified** by Smart Decisions.

The same entry is available in a secondary expander on Decisions. Quick Start's
Smart Paste continues to construct a *profile draft*, not a scenario.
Both workflows share the rule-based amount and frequency recognizers in
`moneylab/free_setup.py`, but their approval and routing differ.

## Technical contract

- `moneylab/decision_language.py`: private intent classification and
  bounded explicit amount extraction. Returns `intent`, `values`,
  `missing`, `gross_income`, `notes` and `ignored`. Supports
  `moving`, `purchase`, `recurring`; otherwise returns
  `unsupported` or `ambiguous`.
- `moneylab/smart_decision_ui.py`: displays the draft for user review,
  rejects unknown recurrence, and pre-populates *temporary*
  session state for the existing page. No query-string financial values.
- `moneylab/scenario_changes.py`: immutable validation of scenario
  modifications: adjust a monthly income/expense, add a monthly expense,
  or deduct a one-time amount from checking/cash. High-yield savings can
  cover one-time costs **only with explicit permission**; retirement,
  investment, and goal balances never fund them.
- `moneylab/moving.py` and `moneylab/decisions.py` reuse the shared
  scenario operations and existing Decimal `project_blocks()` engine.
  No new financial forecasts are generated by text parsing.

### Known parser limitations

This is **not an AI language model**. It is deliberately conservative
about wording, more than one amount in a clause, ambiguous decisions,
gross versus net salary, and missing frequencies.

A statement such as "I make $60,000 per year" does **not** supply monthly
take-home income; it is flagged for user confirmation. An unknown
rent/utility frequency is annotated as a monthly planning assumption,
not silently treated as a verified fact. For an unsupported decision
such as debt refinancing, the interface asks the user to choose an
available template rather than invent a calculation.

The current expense decision supports **one new cost at a time**; the
underlying scenario-operations layer supports *multiple* changes, and
the existing Moving Out Lab already compares multiple changes to rent,
utilities, transportation, groceries and upfront costs simultaneously.
Additional scenario types (job offers, car loans, unemployment) are **not
implemented in this release**.

## Privacy and safety

- No external AI request or paid API key is needed or used by Smart Decisions.
- The interpreter stores a temporary structured draft in Streamlit session
  state. It never writes a profile until the user uses an existing
  explicitly approved profile workflow (Quick Start/My Money).
- The description itself remains in Streamlit widget/session state during
  that browser session, as do manually entered financial values. The
  app has no permanent private-data backend.
- No raw financial data is put in shareable URLs, analytics events or log
  messages by this new feature.
- Validation rejects malformed or excessive amounts and unsupported
  scenario operations. Savings cannot be silently transferred to cover
  spending. The product is a planning tool, not financial advice.
- Unentered expenses remain unknown; no "affordable" certification is made.

## UI cleanup done after integration

- Home emphasizes a single decision description and four suggested
  question shortcuts. Profile setup is optional.
- The sidebar keeps one native Quick Start navigation entry and groups
  examples/advanced tools into expandable secondary sections; clearing a
  profile requires an explicit checkbox.
- Moving Out now shows key monthly/upfront tradeoffs at the top, a readable
  stay-versus-move comparison, and a chart. The precise 6/12/24-month
  values and explanation are available via expanders.
- Decisions expands its language-entry section automatically when a
  draft is awaiting review. Quick Start shows the free methods first
  and places experimental cloud AI in a secondary expander.
- Existing goal, workspace export and advanced What-if paths are retained.

## Automated verification

Run from the repository root:

```sh
python -m pip install -r requirements.txt
python -m compileall -q app.py moneylab tests
python -m pytest -v
python -m streamlit run app.py
```

Core tests:

- `tests/test_smart_decisions.py`: gross-versus-net pay, amount extraction,
  supported/unsupported decisions, missing frequency, multi-change
  scenario operations, liquid-funding permissions and immutability.
- `tests/test_smart_decision_ui.py`: AppTest profile-free and
  existing-profile language-to-scenario routing.
- `tests/test_moving.py` and `tests/test_moving_ui.py`: moving math,
  upfront shortfalls, multiple expense adjustments, results and sample
  forms.
- Existing modular-dashboard, Quick Start, check-in, saved scenarios,
  engine and JSON import/export tests remain in the full suite.

### Manual acceptance checks before broader testing

At mobile and desktop widths: verify navigation, long button labels,
two-column review controls, focus visibility, labels, reading order and
that the moving chart does not overflow. Try an unsupported question,
gross salary, unknown expense frequency, no checking balance, and two
competing financial decisions. Check the original My Money blocks before
and after a hypothetical scenario.

**Streamlit AppTest checks execution, not pixel-level rendering or
assistive-technology behavior.** Real-device / screen-reader checks
have not been established by the automated suite.

## Next development options (after feedback)

1. Better extraction for varied wording and two amounts in a sentence.
2. Profile-aware field reuse with visible and revocable user selection.
3. A job-offer / relocation decision template based on the shared
   multiple-change engine.
4. More detailed scheduling of irregular costs and exact bill dates.
5. A separately reviewed optional LLM extractor only if the rules-based
   flow proves inadequate, with consent and proper cost/privacy controls.
